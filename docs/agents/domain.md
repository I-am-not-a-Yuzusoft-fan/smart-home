# 领域文档

布局：**单上下文（single-context）**。

## 文件位置

- `CONTEXT.md` —— 仓库根目录。领域词汇表：本项目使用的词，以及它们确切指什么。
- `docs/adr/` —— 每个重要决策一个 ADR，命名为 `NNNN-短标题.md`。

## 阅读规则

- 探索代码之前先读 `CONTEXT.md`，用项目自己的词，而不是自己造同义词。
- 任务涉及的区域若有 ADR，先读完再提改动。ADR 记录的是付出了代价才得出的决策。
- 如果这次工作会与已接受的 ADR 冲突，先说明并询问，不要默默推翻它。

## 写入规则

- 一个术语在代码里稳定使用之后，再写进 `CONTEXT.md`。
- 当一个决策难以逆转、或某个真实备选方案因值得记住的理由被否决时，写一条 ADR。
- 保持 ADR 的状态诚实（proposed / accepted / superseded）。
