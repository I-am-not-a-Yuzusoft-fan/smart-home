# 0001 技术栈选型

- **状态**：已接受
- **日期**：2026-11-19
- **决策者**：全组

## 背景

指导书对技术栈是推荐而非强制，硬性要求只有三条：Web 系统（浏览器访问）、五层分层架构、后端 `/api` 前缀 + `/ws/state` 实时推送。

约束条件：

- 8 周工期（第 9–16 周），第 15 周代码冻结。
- 前端基本被 Home3D 绑定：它是 React 19 + Vite + three/r3f + zustand 的栈，指导书 4.3 三条路线都假设在此基础上沿用。
- 组内以 AI 辅助编码（vibe coding）为主，选型要偏向「类型有约束、样板能生成」的语言与工具，减少手写胶水。
- 本机环境已具备：Go 1.27.1、Node 26.13.0、pnpm 12.4.2、Docker 29.8.0、MySQL 26.7.0。

## 决策

| 层 | 选型 |
| --- | --- |
| 展示层 | React 19 + TypeScript + Vite 8 + three `^0.184` + @react-three/fiber `^9` + zustand `^5` |
| UI / 样式 | Tailwind CSS v4 + shadcn/ui（Radix）+ Motion（原 Framer Motion） |
| 服务端状态 | TanStack Query（服务端数据）+ zustand（画布/交互的本地状态） |
| 应用层后端 | Go 1.27 + chi（router/middleware） |
| 契约 | OpenAPI 3.1 为单一来源，`oapi-codegen` 生成 Go server stub 与前端 TypeScript client |
| 数据访问 | sqlc（编译期 SQL 类型检查）+ golang-migrate（迁移） |
| 数据层 | MySQL 8+（主库）+ Redis（设备状态缓存、WebSocket 广播 pub/sub） |
| 实时 | WebSocket，路径 `/ws/state`（指导书 3.3） |
| 设备层 | Mosquitto（MQTT broker，Docker）+ 自研设备模拟器 |
| 部署 | Docker Compose + `start.sh`（指导书 7.1） |
| 主题层 | 二次元主题：设计令牌集中在 `tokens.css`，霞鹜文楷（SIL OFL）标题字体，看板娘组件兼 E4 智能管家入口，统一手绘线性图标；可一键关闭 |

五层与目录的对应（Go 侧）：

```
backend/
├── api/          # oapi-codegen 生成的 server stub + 手写 handler（展示层边界）
├── policy/       # 策略层：场景求值、舒适度算法
├── control/      # 控制层：指令校验、编排、重试、状态广播
├── device/       # 设备层：能力描述、MQTT 适配、模拟器
└── store/        # 数据层：sqlc 生成 + 仓储封装
```

## 备选方案

### MyGo（`egoist/mygo`）— 否决

Go 写桌面应用，窗口用系统 webview 渲染网页，前端也是 Vite + TypeScript，甚至有 `Bind()` 自动生成 `src/mygo.ts` 的类型安全调用——看起来非常像我们要的东西。

但它**不是 Web 框架**：

- `mygo build` 产出的是 `My App.app` / `.exe` / `.deb`，前端产物被嵌进二进制。
- 前端调 Go 走 IPC，不是 `fetch('/api/...')`；没有 HTTP 服务端这一层。
- 指导书 3.3 要求的 `/api` 前缀与 `/ws/state` 在它里面不存在。

指导书 1.2 要的是老师能在自己浏览器里打开的 URL，不是一个需要先启动的 .app。故否决主体系统使用。

附注：mygo 自身是 MIT 许可（v0.10.0），比 Home3D 干净。若后期有余力，可做成一个「桌面中控面板」连到 Web 后端，作为选做的加分演示——但这是可砍项，不得压缩主线。

### TypeScript 全栈（Node + Fastify）— 否决

能力元数据 schema 只写一份，最贴合「新增设备类型不改前端代码」，八周风险最低。否决原因：组内希望后端用 Go，且 Go 的 goroutine 在 WebSocket 广播与设备模拟轮询上更省心。

### Python FastAPI — 否决

指导书默认路线，但组内已选 Go，且引入第三套语言反而增加协作成本。

## 后果

**收益**

- 单二进制部署，Docker 镜像小，`start.sh` 起一套就能演示。
- 契约单一来源：改 OpenAPI 再 `regen`，Go stub 与 TS client 一起更新，减少「字段对不上」这类 vibe coding 高频事故。
- sqlc 把 SQL 也纳入编译期检查，数据层不容易漂移。

**代价与风险**

- 前后端两套语言，schema 变更必须记得跑 codegen，CI 里要卡住。
- **能力元数据是运行期数据，不是编译期类型**——`oapi-codegen` 生成的是接口形状，不是「空调有哪些 capability」。F2「新增设备类型不改前端代码」因此必须靠**数据驱动的动态表单**实现，不能指望类型推导。这是整个项目最容易做错的一点。
- 组内需具备 Go 基本能力；AI 生成的 Go 代码尤其要人工检查分层是否越界——评分表里「分层流于形式」是直接掉档项。
