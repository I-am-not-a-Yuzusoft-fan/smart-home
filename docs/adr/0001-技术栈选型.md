# ADR 0001 · 技术栈选型

- **状态**：已接受（2026-11-19）；**2026-11-20 修订**：TypeScript 版本按 V2 实测改定为 6.0.3，待验证表去掉已结案的一条，实测结论改为「部分过」口径
- **取代**：无（初稿于 commit `0a3cbc1` 撤回重写）
- **相关**：[课程设计指导书](../../课程设计书/2026智能家居系统-课程设计指导书.md) · [指导书调研](../00-指导书调研.md)

## 背景

指导书 7.3 原文：「技术栈不限，以下为推荐组合，可替换但需在设计文档说明理由。」本文就是那份**理由**。

真正不可让的硬约束只有三条：

1. **1.2「必须做」**：一个 Web 系统（浏览器访问），含前端页面与后端服务；数据需持久化；跑通「建图 — 布家具 — 控制 — 看状态 — 触发场景」主线。
2. **第 5 节**：强制分层架构（推荐五层，依赖方向单向）——「这是核心考察点」。
3. **7.2**：本机可一键启动（`start.sh` 或 `docker-compose.yml`），前端访问 `http://localhost:<port>`。

周期 8 周，第 3 周末架构评审。

## 决策

| 层次 | 选型 | 说明 |
| --- | --- | --- |
| 前端框架 | **React 19.3.1 + Vite 8.3.8 + TypeScript 6.0.3** | 指导书推荐项，且均为当前 npm `latest`（无 React 20）。TypeScript 原定 7.0.2，因 typescript-eslint 硬阻断降回 6.0.3，见 [docs/05](../05-技术验证清单.md) V2 |
| 平面图 / 3D | **自研**：three 0.187.0 + @react-three/fiber 9.8.2 + drei 10.7.9 | 替代 Home3D，理由见下 |
| 前端状态 | zustand 5.1.0 | 单一 store，2D 与 3D 同源投影 |
| UI / 主题 | Tailwind v4 + shadcn/ui + Motion | 二次元主题层独立成 CSS tokens，不侵入逻辑 |
| 后端 | **Go 1.27.1 + chi v5.5.0** | 替代 FastAPI，理由见下 |
| 接口契约 | OpenAPI 3.1 + oapi-codegen v2.8.2 | 一份契约生成 Go stub 与 TS client |
| 数据访问 | sqlc v1.31.1 + golang-migrate v4.20.1 + pgx v5.13.0 | 查询由 SQL 生成，不手写 ORM |
| 数据库 | **PostgreSQL 17** | 替代 MySQL |
| 实时通信 | WebSocket `/ws/state`（coder/websocket v1.8.15） | 状态推送；降级为轮询 |
| 设备接入 | 自研模拟器（HTTP） | 指导书推荐项 |
| 部署 | Docker Compose + `start.sh` | 一键启动 |
| 桌面壳 | mygo 0.10.0（**第二阶段形态适配**） | 同一个 React 前端在 webview 里跑 |

## 五层与目录映射

| 层 | 职责 | 落点 |
| --- | --- | --- |
| 展示层 | 平面图/3D、设备面板、场景编辑 | `frontend/src/{features,components,store,api}` |
| 策略层 | 场景规则求值、温控舒适度算法、滞回 | `backend/policy/` |
| 控制层 | 命令路由、幂等、超时重试、状态广播 | `backend/control/` |
| 设备层 | 驱动接口、能力注册表、模拟器 | `backend/device/` |
| 数据层 | sqlc 查询、迁移脚本 | `backend/store/` + `sql/` |

依赖方向：展示层 →(HTTP/WS)→ 控制层 → 策略层/设备层 → 数据层。**禁止反向**；每层只通过接口通信。

## 为什么偏离推荐组合

**后端：FastAPI → Go。** 单二进制便于一键启动；goroutine 天然适合 WS 广播与多设备模拟；本机已装 Go 1.27.1。代价是两门语言 + 代码生成，初期搭建成本高于纯 TS 全栈。

**平面图 / 3D：Home3D → 自研。** Home3D 仓库**无任何许可证**（GitHub `license: null`、`/license` 返回 404、根目录无 LICENSE），而指导书 4.4 要求「遵守其许可证并署名」——对象不存在；1.2 亦禁止「套用现成平台换皮」。故只借鉴其思想（同一份设计数据、2D 与 3D 两个投影；`engine/` 的吸附、碰撞、依赖算法），不复制代码。

**数据库：MySQL → PostgreSQL。** sqlc 一等公民；平面图 JSON 存 `JSONB`；pgx v5。

## 后果

**正面**

- 一键启动：`docker compose up` 或 `./start.sh`；前端 `:5173` 代理 `/api` 到后端 `:8080`，无跨域。
- 契约先行：F2「新增设备类型不改前端代码」靠**能力元数据驱动的动态表单**实现——能力是运行期数据，不是编译期类型。
- 主题层与逻辑层解耦，二次元化只改 tokens。

**负面 / 风险**

- 自研 3D 需自己写网格吸附、AABB 碰撞、参数化依赖、撤销栈，约 1500–2000 行 TS。
- **前端工作量集中在一人身上**：脚手架、类型模板驱动的动态表单、平面图、三维视口、场景编辑器、主题层全部落在同一名成员。缓解手段是**先定死契约与数据结构**（A 轨产出 OpenAPI 与 `item_type` 模板）再并行推进，而不是削减功能项；三维视口复用平面图的同一份设计数据、只读渲染、不另建模型，因而不构成第二套数据结构。
- 代码生成链（OpenAPI + sqlc）是本项目的新增复杂度，需在第 1 周跑通全链路。
- mygo 桌面壳是外部依赖（v0.10.0，需 Go 1.27 + **Bun**），作为第二阶段的原生形态适配。主线（浏览器 Web）不依赖它，故其进度不阻塞主线；但它本身在计划内，不是预备砍掉的项。

## 否决的方案

- **mygo 作主前端**：其浏览器构建（`mygo build -platform web`，即 `GOOS=js GOARCH=wasm`）只投影 native UI（`package ui` 画在 canvas 上）。网页窗口 `LoadURL` 是空实现、`URL()` 返回 `""`，且 `Bind` binds nothing——React 前端在该构建下无法存在。详见[调研文档第 10 节](../00-指导书调研.md)。
- **纯 TS 全栈（Node + Fastify）**：部署与并发模型不如 Go 直观，「前后端分离」的独立性在答辩时也更弱。
- **FastAPI**：需额外维护 Python 虚拟环境；与 Go 相比无优势。
- **Fork Home3D**：许可证缺失，且其 4120 行前端零 TypeScript、无 API 层，改造量不低于自研。
