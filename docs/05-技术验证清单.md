# 技术验证清单

ADR 0001 与 ADR 0002 里各留了几条「这条决策如果站不住怎么办」。散在两处没人会想起来跑，合并成一份，逐条勾掉。

**判定口径**：每项要么给出「过」的证据（命令输出、截图、生成代码片段），要么明确写「退路已启用」。不允许留「大概能行」。

| # | 验证什么 | 类型 | 怎么算过 | 不成立时 | 结论 |
| --- | --- | --- | --- | --- | --- |
| V1 | three `0.187` × `@react-three/fiber 9.8.2` × `drei 10.7.9` 兼容 | 实验 | `npm ls three` 无 unmet peer；渲染一个立方体无控制台报错，旋转流畅 | 降到 r3f 声明支持的 three 版本 | 待跑 |
| V2 | TypeScript `7.0.2`（原生编译器）与 vite 8 / eslint / typescript-eslint 共存 | 实验 | `tsc --noEmit` 通过；`eslint` 无 parser 报错；`vite build` 成功 | 退回 5.x 最新稳定版，只影响 `package.json` 一处 | 待跑 |
| V3 | oapi-codegen `v2.8.2` 生成的 chi stub 合用，且能处理 Cookie `securityScheme` | 实验 | 由 `openapi.yaml` 生成的 Go 代码能编译；`securitySchemes` 生成出可引用的类型 | 手写 handler，只保留 TS client 生成这一半 | 待跑 |
| V4 | mygo `0.10.0` 最小壳能加载我们的构建产物 | 实验 | `mygo build` 成功，窗口打开后页面可交互、能拿到 HTTP 数据 | 砍掉桌面壳（不阻塞任何评分项） | 待跑 |
| V5 | sqlc `v1.31.1` 的 `jsonb` override 双向生效（写入参数 + 扫描回读同一类型） | 实验 | 自定义 `go_type` 后，insert 再 select 回来的结构一致、无需手写反序列化 | 不用 override，在 handler 层手动 `json.Marshal`/`Unmarshal` | 待跑 |
| V6 | `command_log` 与 `state_history` 能同事务写 | 实验 | 同一 `pgx.Tx` 内写两表，中途失败后回滚，两表都无残留 | `command_log` 先独立提交、`state_history` 后写（弱一致，可接受） | 待跑 |

| V8 | 两种角色（`admin` / `member`）是否够用 | 评审 | 用五个场景 + F1 全部操作走一遍，不出现「第三种人」 | 加 `viewer` 角色，S7 提前触发 | 待跑 |

## 什么时候跑

- **V1–V6**：第 9 周内跑完（约半天到一天）。它们决定 ADR 0001/0002 是否成立，第 11 周才发现就得改栈。
- **V7**：写 `sql/seed.sql` 时顺手算，不需要额外时间。
- **V8**：第 10 周用例做完后评审，因为它依赖「谁在做什么」的完整列表。

## 为什么值得花这半天

V1–V6 里任何一条不成立，影响面都不是一行代码：

| 若失败 | 波及范围 |
| --- | --- |
| V1 | 三维视口的整个渲染层 |
| V2 | 前端全部文件（TS 版本换 = 重装依赖 + 修类型） |
| V3 | 后端所有 handler 的签名与路由注册方式 |
| V4 | 第二阶段形态适配，不影响主线 |
| V5 | 数据层每个读写 jsonb 的查询 |
| V6 | F4「命令超时反馈」的证据链设计 |

反过来，这六项都过了，第 10 周的需求分析与第 11 周的接口定义就可以直接往上写，不需要再回头动地基。
