## 1 课程理论与实验五评分口径（一手提炼）

### 1.1 《第6章 软件设计-2026.pptx》（Slides 84–95）核心原则

1. **Theo Mandel 三条黄金规则（Slides 85–87 & Slide 95 AI 体检）**：
   - **① 用户操纵控制**：不强迫用户进入不必要动作；提供灵活交互；交互可中断和撤消；熟练用户可定制；**使用户与内部技术细节隔离开来**；允许直接操纵屏幕对象。
   - **② 减少用户的记忆负担**：减少短期记忆要求；建立有意义的缺省值；定义直观的快捷方式；视觉布局基于真实世界象征（我们的 2D 户型图天然契合）；**以不断进展的方式揭示信息**（渐进披露，不要把所有高级开关一次全摊开）。
   - **③ 保持界面一致**：把当前任务放入有意义语境；应用内按钮/状态色/布局一致；不随意违背既有交互预期。
2. **四个模型对齐（Slide 88）**：消除「设计模型 / 用户模型 / 心理模型 / 实现模型」之间的落差——**当前场景编辑器让人觉得不直观，本质是把“实现模型”（JSON 树、`all/any`、`valueFrom: comfort`、`runMode`）直接暴露给了用户，而非映射到用户的“心理模型”（如果…就…，否则…）**。
3. **GUI 七条设计规则（Slide 94）**：
   `(1) 一致性`、`(2) 通用性`、`(3) 功能性`、`(4) 视觉组织结构`、`(5) 减轻短期记忆负担`、`(6) 预防操作错误，有效反馈`、**`(7) 风格创新性，鼓励探索`**——第 7 条为我们的**二次元主题皮肤与看板娘交互**提供了直接的课程理论依据。

### 1.2 《实验五 应用系统的用户界面设计》核心要求与可迁移评分点

对照 `实验五 应用系统的用户界面设计-学生用修订.docx`（§3、§5、§8、附录 A–C）：

- **以用户为中心五步循环（§3.1）**：理解用户与任务 → 信息架构与导航 → 显示内容分析 → 交互与原型 → 启发式评估与迭代。
- **信息架构与导航（§3.2，15 分）**：层级可控，**重要任务 3 次点击内可达**（对应本仓库 `02-需求规格说明书.md` `NFR-7` 与指导书 §2.3）。
- **显示内容三类映射与统一设计系统（§3.3，15 分）**：文字报告类（单位/精度/重点前置）、图形化类（平面图/图例/状态色一致）、多媒体类；视觉遵循**对比、重复、对齐、亲密性（CRAP）**，建立统一的色彩（含状态色）、字体、字号、间距、图标、组件规范。
- **交互与状态反馈（§3.4–3.5，15 分）**：界面状态必须覆盖**正常态、加载态、空态、错误态**，且与状态机一致；异常可理解、可恢复；**高风险操作（如删除场景/删除类型/清空户型）必须有二次确认防误**（且不应依赖原生 `window.confirm`）。
- **尼尔森十大启发式自查与可访问性（§5 任务 6，10 分）**：系统状态可见、与现实匹配、用户可控自由、一致性、防错、识别而非回忆、灵活高效、极简美观、容错恢复、帮助文档；同时满足 `1366×768` 无横向滚动条挤压（`NFR-15`）。

## 3 第一优先：基于现有技术栈的优秀前端设计方案

我们的底座（**React 19 + TypeScript + Vite 8 + Tailwind CSS v4 + Konva + Zustand**）非常现代，无需推翻重写，直接按 `ADR 0001` 补齐设计系统与组件层即可实现质的飞跃。

### 3.1 设计系统升级：Tailwind v4 `@theme inline` + Konva 桥接

- **CSS-First 多主题 Token 体系**：在 `frontend/src/styles/tokens.css` 中使用 Tailwind v4 原生 `@theme inline` 把语义变量映射到 utility class，并用 `oklch()` 定义感知均匀的色板，涵盖：
  - 表面层级：`--bg`、`--surface`、`--surface-elevated`、`--surface-glass`、`--overlay`
  - 语义状态：`--primary`、`--accent`、`--success`、`--warning`、`--danger`、`--info`（及其 `-soft` 背景与 `-foreground` 文字色）
  - 几何与质感：`--radius-sm/md/lg`、`--shadow-sm/md/lg`、`--blur-panel`、`--font-sans`、`--font-display`
  - **画布专用色板**：`--canvas-bg`、`--canvas-grid`、`--canvas-wall`、`--canvas-wall-selected`、`--canvas-room-fill`、`--canvas-dim`、`--canvas-item-device`、`--canvas-item-furniture`
- **Konva 主题桥接 Hook（`useCanvasTheme()`）**：由于 Canvas 2D 无法直接读取 CSS `var()`，写一个 20 行 Hook 在 `theme` 切换时通过 `getComputedStyle(document.documentElement)` 读取 `--canvas-*` 传给 Konva 节点，实现**DOM 与 2D 户型画布同步换肤**。

### 3.2 组件库与图标体系（兑现 ADR 0001）

| 依赖 | 作用 | 落地收益 |
| --- | --- | --- |
| **`lucide-react`** | 矢量图标库 | 立即渲染 `item_type.icons`（空调/灯/窗帘/温湿度/光照/人体/沙发），全站工具栏图标化 |
| **`shadcn/ui`（Tailwind v4 + React 19）** 或 Radix 原语 | 无障碍基础组件 | 优先引入 `Button`、`Switch`、`Slider`（接进 `CapabilityForm` 实现拖动调亮度/设温度！）、`Sheet`（侧滑抽屉）、`Dialog`/`AlertDialog`（替换 `window.confirm`）、`Tabs`、`Tooltip`、`DropdownMenu` |
| **`sonner`** | 全局 Toast 通知 | 统一承接命令成功/超时/离线/让位提示，支持操作回显与重试入口 |
| **`motion`**（ADR 0001 已选型） | 微交互与动效 | 面板滑入、步骤时间线状态跃迁、看板娘气泡动画，全局遵守 `prefers-reduced-motion` |

### 3.3 核心布局与交互重构（治本解决「不直观」）

1. **顶部导航瘦身 + 浮动画布工具栏（借鉴 Figma / Home Assistant Lovelace）**：
   - **顶栏（固定 52px，左中右三段）**：
     - 左：Logo + 户型标题 + 房间/设备概览胶囊；
     - 中：**主模式切换分段器**（`平面图控家` / `场景编排` / `类型模板` —— 3 次点击内直达全部核心功能）；
     - 右：一键快捷场景按钮（回家/离家/睡眠）+ **主题皮肤切换器** + 账号菜单（含「推进60分钟」等演示辅助收入下拉菜单）。
   - **底部居中浮动工具栏（Floating Pill，毛玻璃阴影）**：把画墙、画弧、网格、标注、底图、撤销/重做、全览、缩放比例收进画布底部浮条，彻底解放顶栏与 1366×768 空间！
   - **左右侧栏支持一键折叠**：默认展开，窄屏或演示时可折叠，画布占比提升至 80%+。
2. **场景面板去全屏化 → 右侧滑出抽屉（`Sheet`，不遮挡平面图！）**：
   - 点「场景」不再黑屏遮住整个户型，而是从右侧滑出 `420px` 半透明毛玻璃抽屉；
   - 点击「回家 / 离家」时，**左边平面图上的灯亮、窗帘开合、空调温度与状态脉冲动画实时同步变化**，答辩视觉冲击力拉满！
3. **场景编辑器「心理模型化」重构（彻底消灭技术黑话）**：
   - 去掉所有英文内部词：`guard` → **「启动前提」**，`all/any` → **「全部满足 / 满足任一」**，`choose / when / then / else` → **「如果…那么…否则…」**，`valueFrom: comfort` → **「智能舒适温控（按季节自动算温）」**，`runMode` / `continueOnError` 收进可展开的 **「高级执行选项」**（渐进披露！）。
   - 步骤卡片可视化：每张卡片左侧带彩色步骤类型图标（⚡ 动作 / ⏱ 延时 / 🔀 条件分支），中间用一句自然语言总结（如「把 **客厅主灯** 的 **亮度** 设为 **70%**」），点击卡片才展开编辑表单，平时保持清晰易扫读的时间线流！
4. **设备控制直接操纵（`CapabilityForm` 升级）**：
   - `bool` → `Switch` 开关（点击立即下发，无需再点确认按钮）；
   - `number` → `Slider` 滑杆 + 数值步进器（松手即下发，带防抖）；
   - `enum` → 分段按钮组（Segmented Control，如空调「制冷 / 制热 / 送风」一键点选）。

## 4 进阶版本：二次元内容的自定义美化架构

核心设计原则：**「工程专业风做默认底盘，二次元美学做零侵入插件层」**——答辩面对偏传统评委可一键切回「标准工程白」，展示亮点与自用时一键切到「二次元定制主题」，两全其美。

### 4.1 多套内置主题 + 用户自定义皮肤引擎（`[data-theme]`）

通过 `document.documentElement.dataset.theme` + `useThemeStore`（Zustand + `localStorage` 持久化）实现零重载瞬切：

| 主题 ID | 风格定位 | 视觉特征 |
| --- | --- | --- |
| `studio`（默认） | 清爽工程白 | 高对比度低饱和蓝灰，论文截图与正式评审零争议 |
| `sakura-glass` | 二次元·樱花玻璃拟态 | 暖樱白/浅粉渐变底、`backdrop-filter: blur(14px)` 磨砂卡片、柔和粉紫主色、圆角 `12px`、圆润中文字体（如「霞鹜文楷」或圆体回退） |
| `ark-hud` | 二次元·战术暗色 HUD | 参考《明日方舟》/《蔚蓝档案》干净工业二次元 HUD：深蓝灰底 + 青/橙高亮描边 + 细斜角/网格点阵质感 + 等宽数字读数 |
| `custom` | **用户自定义皮肤** | 提供「外观自定义」抽屉：自定义**主题主色**、**上传本地背景壁纸（存 IndexedDB / ObjectURL）**、**调节卡片毛玻璃透明度与模糊度**、**圆角风格（锐利/圆润）**、**字体切换** |

### 4.2 二次元看板娘 / 智能家居小助手（`<MascotLayer />`）

放在 `frontend/src/features/mascot/`，作为独立浮层挂载在 `App` 右下角（支持拖拽位置、一键隐藏/展开，**不侵入任何业务 store，只订阅 `useLiveStore` 的状态变化**）：

1. **阶段一（轻量高性价比，推荐先落地）—— 立绘/Q版角色 + 动态状态气泡**：
   - 使用高质感静态/多差分立绘（正常/开心/提醒/休眠 4 张表情差分，支持用户自行上传替换立绘 PNG！），配合 `Motion` 做轻微呼吸起伏、鼠标悬停微倾与点击反馈；
   - **真正与系统业务联动（不是死摆件！）**：
     - 触发「回家」并收到 `run_step.note` 时，看板娘切「开心」表情并弹出对话气泡：*「欢迎回家！当前室温 31.5℃、湿度 68%，已按夏季策略把客厅空调设到 26℃ 啦~」*；
     - 顶层守卫拒绝执行时，切「疑惑/提醒」表情：*「客厅现在好像没人哦，先不执行回家模式啦~」*；
     - 手动接管让位触发时：*「明白！接下来 30 分钟都听你的，我先不自动调空调~」*；
     - WS 断线时切「休眠/离线」表情提醒重连。
   - 这直接把 F5 的「可读依据文案」和未来 E4「智能管家」的交互感拉满，且零 WebGL 性能负担、零外链失效风险！
2. **阶段二（可选进阶）—— Live2D 实时模型（`pixi-live2d-display` / `oh-my-live2d`）**：
   - 在 `<MascotLayer />` 内部留一个渲染适配器接口（`StaticSpriteRenderer` vs `Live2DRenderer`）；
   - 如需真 Live2D，可懒加载 `pixi.js@7` + `pixi-live2d-display` + `live2dcubismcore.min.js`，加载开源许可的 `.model3.json` 模型，实现鼠标视线跟随与点击头部动作反馈（注意严格遵守模型与 Cubism Core 许可协议，且在 `pointer-events: none` 容器下避免挡住平面图操作）。

## 5 建议分阶段实施路线（供下一步 `/plan` 或 `/grill-me` 拍板）

1. **阶段 1（地基与设计系统，1 天）**：升级 `tokens.css`（Tailwind v4 `@theme inline` + 完整语义变量 + 3 套内置主题）、清掉所有组件硬编码颜色、加 `useCanvasTheme()` 桥接 Konva、装 `lucide-react` 接通全站与设备类型图标。
2. **阶段 2（布局与交互体验治本，1–2 天）**：引入 `shadcn/ui` 核心原语（`Switch`/`Slider`/`Sheet`/`AlertDialog`/`Sonner`），顶栏瘦身 + 底部浮动工具栏 + 侧栏可折叠；把 `ModesPanel` 改成右侧不遮画布的 `Sheet`；重写 `ModeEditor` 去掉全部英文技术术语并做成自然语言卡片流。
3. **阶段 3（二次元自定义美化专题，1 天）**：上线「外观自定义」面板（内置 3 皮肤 + 自定义主色/壁纸/毛玻璃透明度）与 `<MascotLayer />`（多表情差分 + 用户自定义立绘上传 + 联动 `useLiveStore` 实时语音/文字气泡，预留 Live2D 适配器位）。
